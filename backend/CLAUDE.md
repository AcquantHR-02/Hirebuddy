## Conventions
- groupId `com.jobportal`, artifactId `kaamsathi`; root package `com.jobportal.kaamsathi`; packages `com.jobportal.kaamsathi.<module>.<layer>` (e.g. `auth.service`).
- Module borders: a module owns its tables; only its own `repository/` touches them. Other modules call its `service/`, never its `repository/` or `entity/`. `common/` = no business logic.
- ONE DB `kaamsathi_db` (utf8mb4), created by hand once; tables only via Flyway (one `db/migration/` folder, versions global V1, V2…); `ddl-auto=validate`; never edit a run migration.
- All endpoints under `/api/...` (e.g. `/api/auth/login`). App port 8080.
- Creds: `backend/.env` (gitignored; template `backend/.env.example` committed). yml imports `optional:file:./.env[.properties]`. OS env vars win if set. Don't set new Windows env vars. Names: `DB_USER`, `DB_PASSWORD`, `ADMIN_EMAIL`/`ADMIN_PASSWORD`, `JWT_PRIVATE_KEY_PATH`/`JWT_PUBLIC_KEY_PATH`, `DEV_EXPOSE_TOKENS` (local only, default false).
- Versions only in `pom.xml` via Boot BOM in `dependencyManagement`. Plugins need explicit `${spring-boot.version}`.
- Own pom (not spring-boot-starter-parent) so every setting is visible.
- Inject `Clock`, never `Instant.now()`. One `Clock` bean in `common/config/AppConfig`.
- IDs: UUID `CHAR(36)` (`@JdbcTypeCode(SqlTypes.CHAR)`); timestamps UTC `DATETIME(6)` ↔ `Instant`; enums `@Enumerated(STRING)`.
- No Lombok; entities: protected no-arg ctor, public ctor, getters only (behaviour methods later). Request DTOs = records with validation.
- Depend on interfaces (`PasswordEncoder`, `Clock`, `JwtEncoder`), not implementations.

## Folder structure (user: strict + professional, 2026-11-13)
Full tree: Reference §7. Style = MODULE FIRST, THEN LAYERS inside. `src/main/java/com/jobportal/kaamsathi/`:
- `KaamsathiApplication` (main only, the only class at root).
- `common/` (no business logic): `config/` (AppConfig: Clock, PasswordEncoder; CorsConfig) · `exception/` (ApiException, GlobalExceptionHandler, ErrorCode) · `dto/` (ApiError, PageResponse) · `security/` (SecurityConfig, JwtService, Role, security error handlers) · `util/` (only if needed).
- Each business module (`auth`, `company`, `seeker`, `job`, `masterdata`, `application`, `payment`, `file`, `notification`, `admin`) uses the same inner folders: `controller/` · `service/` · `repository/` · `entity/` (entities + their enums) · `dto/` (FLAT, no request/response sub-folders — user 2026-11-14; names end in `Request`/`Response`) · `mapper/` (only if needed) · `event/` (later) · `scheduler/` (if needed).
- Example auth: `controller/` SignupController, AuthController · `service/` SignupService, LoginService, TokenService · `repository/` UserRepository, RefreshTokenRepository · `entity/` User, UserStatus, RefreshToken · `dto/` SignupRequest, LoginRequest, RefreshRequest, UserResponse, TokenResponse.
- Folder names lowercase singular (`controller`, not `controllers`). A module has only the layer folders it needs; create a folder only when its first file comes.
- Journey: controller (HTTP + validation) → service (rules, @Transactional) → repository (DB) → entity. Entities never leave the service layer; DTOs go in/out.
- Resources: `application.yml` (+ `application-dev.yml` profile when needed) · `db/migration/` · `templates/email/` (later). Tests mirror main packages in `src/test/java`.
- Backend root: `pom.xml`, `README.md` (later), `.env.example`, `postman/` (with first endpoint).
Write files UTF-8 without BOM (PowerShell 5 adds BOM → javac "illegal character \ufeff").
